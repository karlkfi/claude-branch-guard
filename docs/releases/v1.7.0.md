Fewer git/gh approval prompts in Claude Code, with the human kept at the protected-branch boundary.

> [!NOTE]
> **This release is about a mode that was treated as unattended and isn't.** `auto` sat in the non-interactive set, so every **ask** became a **deny** there. An `auto` session has somebody at the keyboard and the prompt reaches them, so the conversion removed the human rather than protecting them. Nothing new auto-approves: every decision that moved went from **deny** to **ask**, which still blocks. `dontAsk` and `bypassPermissions` are unchanged.

## Highlights

**[`auto` is an interactive mode](https://github.com/karlkfi/claude-branch-guard/blob/v1.7.0/README.md#configuration).** `NON_INTERACTIVE_MODES` held `auto`, `dontAsk`, and `bypassPermissions`, and `confirm()` turns a would-be `ask` into a `deny` for anything in that set — the guard failing safe where no human can answer. The premise held for two of the three. An `ask` in `auto` reaches Claude Code's standard permission prompt, and somebody answers it; workspace-guard, measured on 1.10.0, treats `bypassPermissions` alone as human-free, and branch-guard was the outlier.

A denial does not stop the work, though — it reroutes it, and both measured cases ended somewhere worse than the command that was blocked:

* **Cutting a release could not finish in-session.** Creating an annotated tag was never gated, and publishing one always asks under `strict`. In `auto` that ask was a refusal, so a session could tag locally and then publish neither the tag nor the commit it points at. Tagging finished in the user's terminal every time ([#33](https://github.com/karlkfi/claude-branch-guard/issues/33), closed having fixed only the wording of the denial).
* **A denied `git restore` became a hand-edit.** A session that could not run `git restore file.txt` edited the file back to its `HEAD` content by hand instead ([#78](https://github.com/karlkfi/claude-branch-guard/issues/78)). Same end state, no atomicity, no guarantee the result matched `HEAD`, and nothing in the log to review — the gate had blocked the safe mechanism while permitting the unsafe one.

So `auto` now asks, and `dontAsk` and `bypassPermissions` still deny. Adding a mode back to that set is a claim that nothing there can answer a prompt; measure it before making it, because the name is not the measurement.

**[What this narrows: the break-glass](https://github.com/karlkfi/claude-branch-guard/blob/v1.7.0/README.md#break-glass-branch_guard_override).** v1.6.0 shipped `BRANCH_GUARD_OVERRIDE` for exactly the dead end above, and the `git restore` case was its motivating example. That example no longer plays out in `auto`, which prompts. Nothing about what the prefix lifts has changed — it is simply now for `dontAsk` and `bypassPermissions`, the two modes that still cannot prompt.

## Upgrading

**No steps.** Nothing was removed, no configuration changed meaning, and nothing that runs without a prompt today started prompting.

Third-party marketplaces have auto-update **off by default**, so an install pins its version until you turn it on or update by hand ([Upgrade](https://github.com/karlkfi/claude-branch-guard/blob/v1.7.0/README.md#upgrade)):

```bash
claude plugin marketplace update branch-guard
claude plugin update branch-guard@branch-guard
```

Either way a restart is needed — the hook is registered at startup, so a running session stays on the version it loaded.

**Changes that need no action, but will be visible.** If you run sessions in `auto`, you will see prompts at v1.7.0 where v1.6.0 returned a refusal — a commit to `main`, a tag publish, a `git restore`, an edit on a protected branch. That is the whole change, and it is the same set of operations either way. **If you were relying on `auto` to block without prompting, `dontAsk` is the mode that still does that.**

## Decision surface

Measured by running the v1.6.0 hook and this one over the same throwaway repo: `origin` carrying `main` and `claude/topic`, with the session sitting on `claude/topic` except where a row says otherwise.

Under `auto`, which is the only mode that moved:

| command | v1.6.0 | v1.7.0 |
|---|---|---|
| `git commit -m x` *(on `main`)* | deny | **ask** |
| `git push origin main` | deny | **ask** |
| `git push origin v1.7.0` *(tag publish under `strict`)* | deny | **ask** |
| `git push --tags` | deny | **ask** |
| `git reset --hard HEAD~1` *(on `main`)* | deny | **ask** |
| `git clean -fd` | deny | **ask** |
| `git restore file.txt` | deny | **ask** |
| `git branch -D main` | deny | **ask** |
| `git stash drop` | deny | **ask** |
| `git config --global user.name x` | deny | **ask** |
| `gh repo delete o/r --yes` | deny | **ask** |
| `Edit file.txt` *(on `main`)* | deny | **ask** |
| `BRANCH_GUARD_OVERRIDE=r git reset --hard HEAD~1` *(on `main`)* | deny | **ask** |
| `git status` | allow | allow |
| `git push origin claude/topic` *(the worktree branch)* | allow | allow |
| `git push --follow-tags origin claude/topic` | allow | allow |
| `BRANCH_GUARD_OVERRIDE=r git restore file.txt` | allow | allow |

**Nothing new auto-approves.** Every row that moved went from **deny** to **ask**, and both of those block the command — the difference is whether there is an answer to give. The set of commands that run without a prompt is the same as at v1.6.0, which is what the `allow → allow` rows are there to say.

Every other mode decides exactly as it did:

| command | mode | v1.6.0 | v1.7.0 |
|---|---|---|---|
| `git push origin main` | `dontAsk` | deny | deny |
| `git commit -m x` *(on `main`)* | `dontAsk` | deny | deny |
| `git restore file.txt` | `dontAsk` | deny | deny |
| `BRANCH_GUARD_OVERRIDE=r git restore file.txt` | `dontAsk` | allow | allow |
| `git push origin main` | `bypassPermissions` | deny | deny |
| `git push origin main` | `default` | ask | ask |
| `git restore file.txt` | `default` | ask | ask |

## Validation

**412 specs, green on Linux across Python 3.10–3.13 and on Windows under Git Bash**, on the release commit itself ([run](https://github.com/karlkfi/claude-branch-guard/actions/runs/32125592422)). Every fixture reaches the hook through `hooks/run-python-hook.cmd`, the exact command `hooks/hooks.json` registers, and two fixtures assert that directly: one greps the suite for any invocation outside the launcher, the other pins both helpers to it. A `CASE_FLOOR` catches a suite that silently collapses because setup failed or a section exited early.

The suite grew by 10 cases since v1.6.0, and the shape of the additions is the point rather than the count. Every fail-safe fixture moved to `dontAsk` and gained an `auto` control asserting `ask` — across the push, tag, commit, edit, destructive and break-glass paths — because a suite that only pinned the denial would have passed with `auto` either in the set or out of it. Putting `auto` back fails seven of them, including the two that assert reason wording: an `auto` ask has to invite a confirmation, and it must not advertise the `BRANCH_GUARD_OVERRIDE` prefix, since that hint is for a denial the prefix would actually lift.

What the suite does not assert: it drives the hook's JSON contract in a throwaway repo, not Claude Code's own permission plumbing. Whether an `ask` in `auto` actually reaches a human is a claim about Claude Code rather than about this hook, and no fixture here can settle it. What backs it is the two sessions above that hit the dead end, and workspace-guard 1.10.0 drawing the same line at `bypassPermissions`. It is the premise this release rests on, which is reason to state it as one.

## Security

**No advisory, and no dependencies to bump** — the hook is stdlib-only Python and the plugin ships no third-party code.

This release moves a fail-safe, so state plainly what that costs. The `ask` → `deny` conversion exists because a prompt nobody can answer is worse than a refusal that names the reason, and its value depends entirely on the premise that the mode has nobody in it. For `auto` the premise was false, so the conversion bought no safety and spent the human — the operation still had to happen, and it happened through whatever path was not gated. What replaces it is the prompt, which is the same boundary every interactive mode has always had.

**No auto-approval was added anywhere.** The decision table above is the evidence: every moved row lands on **ask**, no row moved to **allow**, and the modes with genuinely nobody present still deny. The protected-branch set, the push policies, the classifier, and the break-glass are all untouched by this release.

Guarantees stay best-effort by design. Claude Code ignores hook decisions entirely under `bypassPermissions`, so anything you need to hold unconditionally still belongs in a git `pre-push` hook or server-side branch protection.
