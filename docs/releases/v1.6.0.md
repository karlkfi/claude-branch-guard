Fewer git/gh approval prompts in Claude Code, with the human kept at the protected-branch boundary.

> [!NOTE]
> **This release is about the prompt nobody can answer.** In a non-interactive mode an **ask** is emitted as a **deny**, and a deny does not stop the work — it reroutes it, often through something less safe than the command that was blocked. Three forms that used to ask now auto-approve, each one narrow. Nothing that touches a protected branch moved, and nothing got stricter.

## Highlights

**[A break-glass for a denial with no answer](https://github.com/karlkfi/claude-branch-guard/blob/v1.6.0/README.md#break-glass-branch_guard_override).** A session that could not run `git restore file.txt` edited the file back to its `HEAD` content by hand instead. Same end state, no atomicity, no guarantee the result matched `HEAD`, and nothing in the log to review — the gate had blocked the safe mechanism while permitting the unsafe one. Where no ungated equivalent exists, and you cannot delete a branch by editing a file, the state is simply stranded. So one command prefix now lifts an ask whose damage stops at this machine:

```bash
BRANCH_GUARD_OVERRIDE="reverting a superseded local change" git restore file.txt
```

The reason is required, a bare `BRANCH_GUARD_OVERRIDE=` lifts nothing, and the reason is echoed into the emitted decision so the approval is on the record. Two locks bound what it reaches, and both are load-bearing. The subcommand must be one that can lose only state this machine holds — `restore`, `switch`, `branch`, `tag`, `worktree`, `stash`, `reset`, `clean`, `config`, `reflog`, `filter-branch`, `gc` — which puts every `push` form and every `gh` form outside it. And the verdict must not be one a protected branch caused: that class is unliftable by construction rather than by a list, so `git reset --hard` on `main`, `git branch -D main`, and anything you add to [`BRANCH_GUARD_PROTECTED_BRANCHES`](https://github.com/karlkfi/claude-branch-guard/blob/v1.6.0/README.md#configuration) stay denied whatever reason you give.

It is a command prefix rather than a `settings.json` variable because a `PreToolUse` hook inherits Claude Code's environment, not the one the command is about to run in. An env-var override could only be switched on for a whole session, by hand, which is the opposite of scoping it to the moment.

**[A leased rewrite of one other unprotected branch](https://github.com/karlkfi/claude-branch-guard/blob/v1.6.0/README.md#push-guard).** Undoing a bad rebase means rewriting one branch from another: fix it up on a scratch branch, then push that over the original. The destination is never the worktree branch, so under `strict` every spelling of it asked — and in a non-interactive mode that ask is a denial, so the branch could not be repaired at all. Naming the destination in a lease opens the path:

```bash
git push --force-with-lease=claude/topic origin HEAD:claude/topic
```

This rests on the same argument as the non-force `git branch` spellings, that git enforces the check itself: the push aborts unless the remote is still at the commit the command named, so it cannot land on top of work the session has not seen. What a lease does **not** establish is that the destination is unshared. That stays branch-guard's own question, answered by the protected set and checked ahead of the whole `strict` block, so no lease can reach past it. A bare `--force-with-lease` names no ref and does not qualify; deletions are excluded in both spellings; and `--no-force-with-lease` clears every lease collected so far, as it does in git.

**[`git branch -D` when the only orphan is a merge git can reproduce](https://github.com/karlkfi/claude-branch-guard/blob/v1.6.0/README.md#git-branch-what-the-session-owns-not-how-the-verb-looks).** Recoverability is a property of the tip, and force-delete cares about a slightly wider thing: what the delete would orphan. The two come apart for exactly one shape — a scratch branch that merged an integration ref to check something, whose tip is unreachable *because* it merged, while the only commit nothing else names is that merge:

```bash
git switch -c tmp-basecheck
git merge origin/main       # does the gate still pass over the merged tree?
git switch -
git branch -D tmp-basecheck
```

So the hook re-runs the merge. `git merge-tree --write-tree` recomputes a tree from the two recorded parents, and if it matches the tree the commit records, the commit holds nothing a plain `git merge` would not produce again. "It is only a merge" is not the property being established: a hand-resolved conflict lives in that merge's tree and nowhere else, so re-running the merge is what separates a derivable commit from authored work. Every other answer keeps the prompt — a non-merge or octopus orphan, a conflicting or hand-edited merge, more than four orphans, a git predating `merge-tree --write-tree` (2.38, 2022), a read-only object store, a timeout. Only `-D` and `--delete --force` get this; the force move and copy forms keep the tip-only question.

## Upgrading

**No steps.** Nothing was removed, no configuration changed meaning, and no default got stricter.

Third-party marketplaces have auto-update **off by default**, so an install pins its version until you turn it on or update by hand ([Upgrade](https://github.com/karlkfi/claude-branch-guard/blob/v1.6.0/README.md#upgrade)):

```bash
claude plugin marketplace update branch-guard
claude plugin update branch-guard@branch-guard
```

Either way a restart is needed — the hook is registered at startup, so a running session stays on the version it loaded.

**Changes that need no action, but will be visible.** Three forms that prompted at v1.5.0 now auto-approve, listed in **Decision surface** below. If you run sessions in `auto`, `dontAsk`, or `bypassPermissions`, the visible change is larger there than the table suggests: those three were denials rather than prompts, and a denial is what an agent works around.

## Validation

**402 specs, green on Linux across Python 3.10–3.13 and on Windows under Git Bash**, on the release commit itself ([run](https://github.com/karlkfi/claude-branch-guard/actions/runs/32122380746)). Every fixture reaches the hook through `hooks/run-python-hook.cmd`, the exact command `hooks/hooks.json` registers, and two fixtures assert that directly: one greps the suite for any invocation outside the launcher, the other pins both helpers to it. A `CASE_FLOOR` catches a suite that silently collapses because setup failed or a section exited early.

The suite grew by 67 cases since v1.5.0, and the shape of the additions follows from what each relaxation leaves open. A lease establishes that the remote has not moved and says nothing about who else uses the branch, so the push fixtures cross the lease against the protected set rather than covering each separately. The break-glass has two independent locks, so its fixtures cross them too: every `push` and `gh` form refusing to lift, and `reset --hard` and `branch -D` refusing on a protected *and* a configured branch while an overridable subcommand on a private one allows. Config fixtures carry their unset control, since `[configured] … -> ask` on its own would be satisfied by a form that asked unconditionally.

What the suite does not assert: it drives the hook's JSON contract in a throwaway repo, not Claude Code's own permission plumbing. It cannot tell you whether a remote-tracking ref is stale, and it does not exercise the reproducible-merge path against a git older than 2.38 — that version simply keeps the prompt.

## Security

**No advisory, and no dependencies to bump** — the hook is stdlib-only Python and the plugin ships no third-party code.

The break-glass is the change that deserves scrutiny, so state plainly what it is: **self-served**. The agent writes its own reason and the guard checks only that one was given. It buys legibility over the ungated alternative — the operation stays atomic and the reason is recorded — not a second opinion. What keeps it bounded is scope alone, which is why the subcommand set holds only operations whose damage stops at this machine, and why an ask caused by a protected branch is unliftable through a separate mechanism rather than by being left off that list. Treat "could this reach past this machine?" as the question when considering a new entry.

Two of this release's three loosenings rest on git enforcing something itself — the lease abort, and the merge that recomputes — rather than on a probe. The third is the override, which rests on nothing but its scope. All three fail toward the prompt: a probe that cannot answer, a merge that does not reproduce, and a reason that is empty all leave the **ask** exactly where it was.

Guarantees stay best-effort by design. Claude Code ignores hook decisions entirely under `bypassPermissions`, so anything you need to hold unconditionally still belongs in a git `pre-push` hook or server-side branch protection.
